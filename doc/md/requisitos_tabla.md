| ID   | Tipo           | Requerimiento                                                                            | Comentario                                                                                                                  |
| ---- | -------------- | ---------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| R1.0 | Usuario        | El usuario debe poder enseñar una tarea moviendo manualmente el brazo.                   | No debe requerir escritura de código.                                                                                       |
| R1.1 | Usuario        | El sistema debe ser fácil de operar.                                                     | Operación mediante acciones simples: iniciar, grabar, guardar, seleccionar, reproducir, borrar, detener, agarrar y liberar. |
| R1.2 | Usuario        | El sistema debe permitir preparar una nueva tarea rápidamente.                           | La enseñanza de una nueva tarea debería realizarse en pocos minutos.                                                        |
| R2.0 | Manipulación   | El brazo debe agarrar, sostener, trasladar y liberar objetos livianos.                   | Carga objetivo del prototipo: hasta 200 g.                                                                                  |
| R2.1 | Movimiento     | El brazo debe mover objetos entre posiciones predefinidas con precisión funcional.       | Prueba funcional: traslado de un objeto liviano entre dos posiciones.                                                       |
| R2.2 | Movimiento     | El sistema debe ejecutar una misma trayectoria varias veces con resultados consistentes. | La repetibilidad se valida repitiendo una trayectoria grabada sin fallas en toma o liberación.                              |
| R3.0 | Trayectorias   | El sistema debe registrar trayectorias durante una sesión de enseñanza.                  | La grabación debe incluir posiciones articulares necesarias para reproducir el movimiento.                                  |
| R3.1 | Trayectorias   | El sistema debe permitir guardar trayectorias registradas.                               | Cada trayectoria debe poder identificarse posteriormente.                                                                   |
| R3.2 | Trayectorias   | El brazo debe reproducir automáticamente una trayectoria guardada.                       | La reproducción debe seguir la secuencia registrada durante enseñanza.                                                      |
| R3.3 | Trayectorias   | El usuario debe poder seleccionar una trayectoria almacenada.                            | La selección se realiza desde la interfaz local.                                                                            |
| R3.4 | Trayectorias   | El usuario debe poder borrar trayectorias almacenadas.                                   | Una trayectoria eliminada no debe quedar disponible para reproducción.                                                      |
| R3.5 | Trayectorias   | Las trayectorias deben conservarse después de apagar y encender el sistema.              | Requiere almacenamiento persistente.                                                                                        |
| R4.0 | Interfaz       | El sistema debe contar con una interfaz local para operar funciones principales.         | Debe permitir iniciar, grabar, guardar, seleccionar, reproducir, borrar y detener.                                          |
| R4.1 | Interfaz       | El sistema debe informar el estado actual del brazo.                                     | Estados mínimos: listo, enseñanza, grabando, guardado, reproduciendo, finalizado, error y detenido.                         |
| R5.0 | Seguridad      | El usuario debe poder encender y apagar el brazo de forma segura.                        | El sistema no debe iniciar movimientos automáticos inesperados al energizarse.                                              |
| R5.1 | Seguridad      | El sistema debe permitir detener la ejecución ante una condición anormal.                | La detención debe tener prioridad sobre la ejecución de trayectorias.                                                       |
| R5.2 | Inicialización | El brazo debe realizar una preparación inicial antes de operar.                          | Debe preparar servicios de control, verificar estado general y quedar en condiciones conocidas.                             |
| R5.3 | Inicialización | El brazo debe contar con una posición de referencia.                                     | Posición conocida para iniciar o finalizar operaciones de forma ordenada.                                                   |
| R6.0 | Software       | El brazo debe operar localmente sin requerir computadora externa durante el uso normal.  | La computadora integrada ejecuta lógica de control, trayectorias e interfaz.                                                |
| R6.1 | Software       | El software debe organizarse de forma modular.                                           | Módulos mínimos: control, lectura de estado, grabación, reproducción, gestión, interfaz y seguridad.                        |
| R6.2 | Software       | El sistema debe utilizar ROS 2 como plataforma principal.                                | ROS 2 se usa para lógica de control, comunicación entre módulos y futura simulación.                                        |
| R6.3 | Software       | El sistema debe conocer el estado de las articulaciones durante la operación.            | Requiere lectura de estado para grabar, reproducir y detectar condiciones anormales.                                        |
| R6.4 | Software       | El sistema debe enviar comandos de movimiento a los actuadores.                          | Debe permitir movimiento manual asistido, grabación y reproducción automática.                                              |
| R6.5 | Software       | El sistema debe iniciar automáticamente los servicios de control.                        | El usuario no debe ejecutar comandos internos manualmente para operar el producto.                                          |
| R7.0 | Entorno        | El producto debe estar pensado para uso interior.                                        | No está diseñado para intemperie, lluvia, polvo excesivo, humedad elevada o ambientes industriales agresivos.               |
| R7.1 | Alimentación   | El sistema debe alimentarse desde la red eléctrica disponible.                           | Red domiciliaria considerada: 220 VCA, 50 Hz.                                                                               |
| R7.2 | Fabricación    | El brazo debe contemplar construcción de bajo costo.                                     | Estructura principal fabricada mediante impresión 3D y piezas reemplazables.                                                |
| R7.3 | Alimentación   | La fuente principal debe alimentar brazo, computadora integrada e interfaz.              | Criterio preliminar: fuente switching de 12 VCC y 20 A como mínimo.                                                         |
| R7.4 | Actuadores     | El brazo debe usar servomotores inteligentes con realimentación de posición.             | Prototipo basado en STS3215 o equivalentes funcionales.                                                                     |
| R7.5 | Carga          | El brazo debe manipular objetos de hasta 200 g.                                          | La carga útil debe validarse experimentalmente.                                                                             |
| R7.6 | Materiales     | El prototipo debe fabricarse inicialmente en PLA o PLA+.                                 | Para mayor robustez se contempla PETG en piezas estructurales.                                                              |
| R7.7 | Mecánica       | El diseño mecánico debe tomar como referencia SO-ARM100/SO-ARM101.                       | Se construye un único brazo que funciona como enseñanza y ejecución.                                                        |
| R7.8 | Integración    | El sistema debe contar con gabinete o soporte para electrónica, alimentación e interfaz. | Debe proteger componentes internos frente a contactos accidentales.                                                         |
| R8.0 | Validación     | El sistema debe permitir validar el funcionamiento antes de operar físicamente.          | Puede realizarse mediante simulación, pruebas parciales o ensayos controlados.                                              |
| R8.1 | Simulación     | El sistema debe contar con un modelo de simulación.                                      | La simulación debe validar movimientos y funcionalidades antes de la implementación física.                                 |
| R8.2 | Pruebas        | El sistema debe superar una prueba de manipulación.                                      | El brazo debe tomar, trasladar y liberar un objeto liviano.                                                                 |
| R8.3 | Pruebas        | El sistema debe superar una prueba de repetibilidad.                                     | Debe repetir una trayectoria previamente grabada con resultado consistente.                                                 |
| R8.4 | Pruebas        | El sistema debe superar una prueba de precisión funcional.                               | Prueba propuesta: colocar un anillo sobre un dedo de una mano impresa en 3D.                                                |
| R8.5 | Consumo        | El consumo eléctrico debe medirse durante las pruebas del prototipo.                     | Medir reposo, movimiento manual, grabación, reproducción, carga liviana y mayor esfuerzo mecánico.                          |
| R9.0 | Expansión      | El diseño debe contemplar futura visión artificial e inteligencia artificial.            | Fuera del alcance inicial; posible incorporación de cámara y reconocimiento de objetos.                                     |
| R9.1 | Expansión      | El sistema debe contemplar futura telemetría.                                            | Posibles registros: estados, errores, trayectorias, consumo, posición, temperatura o carga.                                 |
| R9.2 | Expansión      | El sistema debe poder evolucionar hacia una interfaz remota.                             | Fuera del alcance inicial; posible panel web, escritorio o herramienta equivalente.                                         |
| R9.3 | Expansión      | El brazo debe contemplar futuras herramientas o accesorios.                              | Posibles variantes de pinza, soportes, adaptadores o efectores finales.                                                     |
| R9.4 | Expansión      | La interfaz local podría incorporar potenciómetros para manejo manual de servos.         | Función deseable para pruebas o manipulación alternativa del brazo.                                                         |
